# 2026-10-19 安全修复与升级

## 部署步骤

1. 在目标数据库执行 `sql/migrations/20261019_file_security.sql`，再发布新后端与前端。脚本可重复执行，增加 `sys_file.owner_id`、索引与文件操作权限；不会重建表或删除业务数据。
2. 升级后所有旧格式 Token 需要重新登录。修改密码（含管理员重置）后，该账号此前所有 Token 在后续请求中失效；前端个人改密成功后直接返回登录页。
3. 需要管理文件的普通管理员，由超级管理员按职责分配下表中的权限。没有管理权限的普通账号仍可上传自己的头像、查看和删除自己上传的文件。
4. 业务附件通过 `/api/system/file/download/{fileId}` 下载。公开静态访问仅保留 `/api/profile/avatar/**`；原先直接使用其他 `/profile/**` 文件地址的业务需切换到授权下载接口。部署代理也应将附件下载交给后端处理，不能再直接公开整个上传目录。

## 文件权限

| 权限 | 范围 |
|---|---|
| `system:file:upload` | 通用及批量文件上传 |
| `system:file:list` | 全局文件列表 |
| `system:file:query` | 查看非本人文件详情 |
| `system:file:download` | 下载非本人文件 |
| `system:file:delete` | 删除非本人文件 |
| `system:file:cleanup` | 手动清理、查看清理日志 |

上传归属使用不可变的用户 ID。历史文件的 owner_id 保持 NULL，不猜测归属；只能由具有相应管理权限的账号操作。历史头像可继续显示，更换时不会自动删除归属未知的旧文件。

头像上传仅允许 JPG/PNG/GIF，最大 2 MiB、宽高最多 4096 像素，后端检查实际图像格式。绑定个人头像时必须是本人上传完成的头像文件。

## 审计处理

- 修改密码接口完全不采集请求内容。
- 其他审计请求和响应按 JSON 字段递归屏蔽 password、passwd、pwd、secret、token、Authorization、Cookie、API key 等敏感内容，不改动原请求或业务响应。
- 日志入库和日志列表读取均执行脱敏，避免历史日志经界面继续暴露密码；无法解析的历史截断载荷整体隐藏。
- 数据库和既有备份中的历史原文不会被本次发布自动改写。需要按实际留存策略清理历史敏感载荷，并评估曾暴露凭据是否需要重置。

## 授权边界

非超级管理员只能分配已启用、菜单权限不超出自身范围的角色，编辑/删除的用户和角色也必须位于自身管理范围内。不能给自己或其他账号增加自身未拥有的权限，不能通过修改菜单权限字符串绕过限制。超级管理员账号和管理员角色具有删除、禁用与保留角色标识保护。

角色菜单范围依据数据库关联检查，接口权限仍由后端方法授权检查；前端传入的角色 ID、菜单 ID 不被视为授权依据。

## 文件清理并发安全

- 上传及批量上传持有文件锁直到数据库事务完成；失败回滚时补偿删除已落盘文件。
- 清理任务互斥；逐文件尝试锁，跳过进行中的上传和未完成的事务。
- 孤儿清理排除最近 `file.cleanup.exclude-recent-minutes` 分钟内修改的文件（至少 1 分钟），删除前重新查询数据库引用。
- 超时清理在拿锁后重新查询状态，避免使用扫描时的旧状态；清理过程挂起外部事务，避免 MySQL 可重复读快照遮蔽新提交的上传。
- 锁使用上传目录下 `.locks/` 中固定数量的文件，由进程内锁及操作系统文件锁共同实现；不将锁文件纳入清理或公开资源。多个实例必须使用同一共享上传目录，且存储文件系统须支持可靠文件锁；不要单独删除 `.locks/`。
- 普通文件删除及头像替换先提交数据库，再执行物理删除；物理删除失败会保留错误日志，残留本地文件可由后续孤儿清理回收。
